# CK-FTZ conformance vectors (`veritor.ftz-f32@1`)

Independent conformance vectors for the scalar flush-to-zero family (E4, EOD 2026-09-11). Generated by
`gen_vectors.py`, which imports **only** the registry (`verity_vllm.registry.prims`) and the registered MUFU tables
(`verity_vllm_numerics.fa2_relation.tables()`) -- never the checker (`ck_ftz.py`) or the guest
(`zk/sp1/programs/ftz/`). Regenerate:

~~~sh
.venv/bin/python e2e/coverage_v1/ftz_vectors/gen_vectors.py
~~~

| file | vectors | the checker must |
|---|---|---|
| `positive.json` | 131 | accept every one (`verdict_all = 1`) |
| `negative.json` | 34 | reject every one (`verdict_all = 0`, every verdict `0`) |

## Vector schema

~~~json
{"id": "mul.sub-out-flushes", "gate": "f32_mul_ftz", "args": ["0x0D800000", "0x30800000"], "claimed": "0x00000000",
 "expect": "accept", "note": "2^-100 * 2^-30 = 2^-130 is subnormal -> +0", "source": "registry:prims.py"}
~~~

`args` are the gate's operand words in the primitive's signature order (`0x`-hex; f32 encodings are 32-bit, the
table row of `mufu_ex2_ftz` / `fa2_inv_sum` is the 64-bit word `(index << 32) | T[index]`); `claimed` is the output
word the vector claims; `expect` is the checker verdict the vector demands. `veritor-ftz-host encode` turns a file
into a `veritor/ftz-conformance/v1` statement (`ck_ftz.encode_conformance` is the byte-identical Python spelling);
the guest commits one verdict byte per vector.

## Negatives (34, every one rejected)

Wrong by 1 ulp (mul, add-tie, ex2, rcp), unflushed subnormal result (mul, add cancellation, sub+sub, ex2, rcp),
unflushed subnormal operand (mul, max, fma-sub addend), wrong sign of zero (mul, add, fma-sub, max, guard), NaN
canonicalised where the rule propagates / propagated where the rule drops it (mul, max, inv-sum), `inf − inf` claimed
`+inf`, double rounding (fma-sub), swapped operands (fma-sub `a↔c`, max), the fma instead of the fma-sub, `+inf`
zeroed / `−inf` kept by the guard, subnormal flushed by the guard, **wrong table row opened** (ex2 row 1 for `x = 1`,
rcp row 1 for `s = 2`), `rcp(−0)` instead of the degenerate 1.0.

## Sources and caveats (read before approving)

* **Registry.** Every positive `claimed` is `prims.<Prim>.evaluate(...)` (source lines: `F32MulFtz` 248,
  `F32AddFtz` 236, `F32FmaSubFtz` 260, `F32Max` 266, `GuardNegInfZero` 272, `MufuEx2Ftz` 426, `Fa2InvSum` 440),
  except the two classes below.
* **`pinned-SSE` (5 vectors).** `F32{Add,Mul}Ftz` evaluate through numpy, so the registry's NaN *payload* rule is the
  host CPU's. The approved backend pins x86-SSE (`zk/sp1/common/src/reduce.rs`). Where AArch64 (this laptop) and
  SSE differ -- the generated NaN of `0·inf` / `inf − inf` (SSE `0xFFC00000`, AArch64 `0x7FC00000`) and two-NaN
  operand order -- `claimed` is the SSE pin and `note` carries the registry-on-this-host word. **Registry finding:**
  the registered function is host-dependent on these inputs; the registry owner should pin one rule in `prims.py`.
* **`registry-as-executed` (2 vectors, `ex2.REGISTRY-ARTEFACT.*`).** `fa2_model.cpp` `mufu_ex2_bits` computes
  `mant >> (-unb)` with a 64-bit shift whose amount exceeds 63 for `|x| ≤ 2⁻⁶⁴`; compiled, that is a mod-64 machine
  shift, so the registered evaluator returns e.g. `ex2(2⁻⁶⁴) = 2.0` and `ex2(−2⁻⁶⁵) ≈ 0.707` where the hardware
  surely returns 1.0. The checker mirrors the **registered function as executed** (`wrapping_shr`); these vectors pin
  that and flag it. **Registry finding** for the owner of `fa2_model.cpp` (the exhaustive sm_89 comparison cited in
  attention-model.md §3.1 should be re-read for this range).
* **`ex2.BOUNDARY.forged-row-word` (1 vector).** A table row with the *right index* and a *forged word* is accepted by
  the relation: table-word authenticity is the table tree's root, which the statement must pin (E6/E7). Listed as a
  positive so the boundary is explicit; not counted as a negative.
* **GPU-captured leaves.** None available: attempt 6's record (`out/records/V5-TINY-bex0-inc-elem-b8177939.md`)
  commits boundary BF16 rows and weights only; no committed leaf holds an f32 operand of an FTZ VU. When E2's
  interior trees land, `ck_ftz.build_many` proves the kernel's actual words directly.
