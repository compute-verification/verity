## What is proved / what is measured / what is assumed

**Proved (certified, sound for every legal partition).** `L(P; F, X)` from `bounds/lower.py` (SPEC §2): the
source term (every non-fixed root that is read must enter some replay unit) and the per-matmul Loomis-Whitney
import charges under the `alpha_eff` operand cost model. Hence `kappa_upper = ADW_matmul_macs / L` is a
certified ceiling on the accumulation-dependent MACs an evaluator can perform per byte of runtime input.

**Measured (exact properties of the declared circuits).** Everything from the operator graph: op shapes,
MAC counts, ADW, the state floor `P`, token/seed bytes, and `U` (the input cost of an explicit legal partition
from `bounds/upper.py`). `U/L` is the bracket on the true `I*`; on tiny circuits the exact solver checks
`L <= I* <= U`. Extraction time and peak RSS of the extractor are measured per workload (see *Extraction scaling*).

**Assumed / simplified (change operator shapes, not the method).** Full `S x S` attention (no causal mask);
activation checkpointing in every block backward; softmax / RMS-norm backward reduced to their elementwise
parts; MoE routing static and balanced with a full expert backward (the MoE block recompute includes the router
and the expert `Wd` products; the router has no dgrad and a top-k-sparse wgrad); LoRA computes all 14 adapter slots (inactive ones fixed) and recomputes the base products in
the backward; ES reward is a scalar loss-gradient proxy; SGD optimiser; embedding scatter-add not modelled;
element widths 16 bit, accumulators 32 bit, token ids 4 bytes. P3 makes no hardware assumption: it is a
dimensionless ratio of the policy's own budgets (training `kappa_L` against honest-inference `kappa_U`). The bound
family charges matmuls only (other kinds contribute 0, sound). **All `L` values in this file are provisional**
(`bounds/lower.py` v1 = state floor + token bytes) until the v2 lower bound is validated.

## Extractor memory incident and safety discipline

Before the fix, the extractor was superlinear in the number of sequences batched through one attention call:
root-level transposes of the batched attention outputs materialised explicit reference tuples, so `2 x 4096`
tokens at 8B did not finish in 5 minutes and an unguarded probe drove the machine out of memory. The
pre-fix measurements (8 `oom-guard` kills at 2 GB within 4-6 s, all `pretrain-dense` with >= 2 sequences per
forward; `inference-dense` at 2 x 4096 was fine, so the blow-up was in the backward consumption of the batched
`AttnSeqBwd` output) are kept in `extract_scaling_before_fix.json` (table *Extraction scaling, before the fix*
below). The fix: weight gradients are now an `AccMatmulTT` composite with token-major operands (edges
`(dY, X)`, `M` = weight rows, `N` = weight cols, `K` = tokens) and the extractor memoises per-member
resolutions; extraction is ~linear in sequences (~0.1 s per sequence at 8B) and the same cases now extract in
1-2 s at < 150 MB (table *Extraction scaling*).

Discipline kept regardless: every build+extract (sweep case, characterization row, scaling probe) runs in
its own child process under `accumulation.sweeps.guard.run_guarded` -- wall-clock timeout, RSS watchdog
(`ps -o rss=` every 0.5 s, SIGKILL above 3 GB, recorded as `oom-guard`), and a cross-process lock so at most one
child runs at a time. `guard.SAFE_LIMITS` only rejects absurd requests now; the pre-fix envelope is
`guard.LEGACY_LIMITS`.

## Observations on the bounds (for the bounds authors)

* **`L_cap` does not grow with `Q`.** In P1 (`pretrain-dense`, 8B, X = 5 MB) the Loomis-Whitney cap is
  `1.018e9` bytes at every `Q` from 4096 to 4 M tokens, so `L = L_source = P` (16.06 GB) throughout,
  `L/token` falls as `1/Q`, and `kappa_L = ADW_matmul_macs / L` grows linearly with `Q` (8.3e3 -> 2.1e6 MAC/B
  from 4096 to 1 M tokens). `U/token` is flat (~2.1e8 B/token, i.e. `U ~ 5e4 x P` at 1 M tokens), so `U/L`
  grows from 56 to 1.4e4. Either the per-op charge is missing a factor of the token dimension (the matmul
  `K`/`M` grows with `Q` but the charge does not), or `F` (unused, see `lower_bound` notes) is what should make
  it scale. Until this is resolved the certified `kappa_L` at large `Q` is not informative.
* **`upper_bound` cannot tile `colsum` at large `Q`.** At `Q = 4,194,304` (8B, X = 5 MB) it raises
  `no legal row tile for op 487 (colsum {'Q': 4194304, 'K': 4096})`: the RMS-norm gain gradient reduces over
  all `Q` tokens and is handled as a row unit; it needs a split over `Q` with a partial-sum reduction (a star
  reduction like the weight gradients) to have a legal partition at any `X`. Same class of failure at
  X = 100 KB for the 128256-wide LM-head rows (`embed`, `lossgrad`) and 28672/53248-wide MLP rows (`add`,
  `swiglu`, `perturb`): one row exceeds `X`, so `U` is undefined there (recorded as `upper_error`).
* **Bound-side memory on the 18k-op LoRA graphs.** `lora` / `hidden-adapter` on `llama3-405b` extract in 6 s
  (< 600 MB) but the child crosses 3 GB during ADW/bounds (an earlier unguarded run peaked at 4.7 GB) and is
  killed (`oom-guard` rows in `sweep_p2.jsonl`). `adw`/`lower`/`upper` on `OpGraph`s with ~18k ops need a
  memory look (per-op ancestor sets?).
* (Superseded) the earlier tight MoE `U/L` (1.4-2.2) was measured when the MoE factory had no expert backward;
  `pretrain-moe` now has the full expert backward (train/inference MACs ~4x) and its P2 rows will be recomputed
  with the grid.

### Findings

* **IR / IR-faithful = 1.0000 for every algorithm on every model** (38 cases: 8 dense algorithms x 4 Llama-3
  sizes, 2 MoE algorithms x 3 MoE models). The extracted graph contains exactly the matmuls the IR is written
  to contain, with the right shapes and copy counts; no MoE expert, top-k slot, GQA head or LoRA factor is
  missing.
* **Training circuits are 1.25-1.26x the textbook 3x count** (`pretrain-dense`, `local-sgd`,
  `rl-policy-gradient`): `BlockBwd` (`algorithms/transformer.py:173-222`) recomputes the block forward except
  the last `Wd` product (activation checkpointing), and `AttnSeqBwd` (`transformer.py:95-119`) recomputes
  `Q K^T`; so weight MACs are `4x forward - Wd` and attention is 9 products per layer (fwd 2, recompute 2,
  bwd 5) instead of 6. Attention is full `S x S` (docstring `transformer.py:11`), i.e. 2x the causal triangle.
* **LoRA / hidden-adapter are 1.42-1.50x the textbook count**: `LoraBlockBwd` (`transformer.py:362-418`)
  recomputes the *whole* block forward including the unused `Wd` base product (`_, ld = proj(h, Wd, ...)`,
  line 399), and all 14 adapter slots are computed whether or not they are active (`registry.py:489`
  simplification). Only 2 head products (fwd + dgrad; the head is frozen, no wgrad).
* **`pretrain-moe` now has the full expert backward** (`MoeBlockBwd` / `ExpertMlpBwd`): train/inference MACs
  are ~4.0-4.1x on Mixtral / DeepSeek-V3 / Qwen3 (the audit table above is regenerated from the current IR). The
  earlier 0.34x figure came from a factory that stopped after the LM-head gradients; that text is superseded.
  The analytic IR model (`characterize.analytic_macs`) mirrors the new backward: the MoE block recompute covers
  the whole block forward including the router and the expert `Wd` products, the router has no dgrad and a
  top-k-sparse wgrad (`D * TOPK` MACs per token), attention backward as in the dense block (5 products).
* Other things the IR does that an analytic count might not expect: the embedding table is
  `accumulated` state but has no gradient/update (`registry.py:311-316`); `es` perturbs every matrix per
  member (`Perturb` ops, not matmuls) and computes one forward per member, so ES MACs/token equal inference;
  `rl-policy-gradient` is one teacher-forced forward+backward over all `Q` tokens regardless of `gen_tokens`.

## Sweeps (Task 3)

Driver: `accumulation.sweeps.run` (module docstring = row schema and resume / redo semantics). Every case runs in a
guarded child (wall clock, 3 GB RSS watchdog, one child at a time); every `lower_bound` / `upper_bound` call has
its own wall-clock limit; a child killed inside one bound call loses only that call (the parent recovers the
rest of the row from a checkpoint line and re-spawns for the remaining `(F, X)`). Rows carry `lower_src` /
`upper_src` (hashes of the bound modules), so `--redo lower --resume` recomputes exactly the rows produced by an
older `bounds/lower.py`.

**Status of the lower bound.** All `L` values below come from `bounds/lower.py` v1, which collapses to the state
floor plus token/seed bytes (`L = L_source`, the Loomis-Whitney cap never binds); they are **provisional** and
every derived quantity (`L/token`, `kappa_L`, `U/L`, `eta_max`, the `L` fits) inherits that status. `U` is a
constructive partition and is trusted. The broad P2 grid and the P2/P3 tables at scale are on hold until the v2
lower bound (SPEC §2.2) is validated against the exact solver; they will be produced with
`--preset p2` and `--redo lower --resume`.

### P3 — efficiency translation

Defined in `accumulation.sweeps.analysis` (docstring). An adversary running a training circuit under the policy's
budgets -- total work `W`, total runtime-input allowance `B` -- can perform at most `M <= kappa_L(train) * B`
target MACs, `kappa_L(train) = |M(C)| / L` being the certified target-MAC-per-input-byte ceiling of that circuit
at `(X, F)` (`|M(C)| = ADW_credited_macs`: accumulation-dependent matmul MACs with the `recompute` ops removed,
i.e. the distinct target products); the adversary's efficiency is `M / W <= kappa_L(train) * B / W`. The policy
calibrates `B / W` so that *honest inference* at the same `(model, X, F)` is efficient: `B / W = 1 / kappa_U(inf)`,
`kappa_U(inf) = all_macs / U(inference)` (inference has `ADW = 0`; its total matmul MACs are its work). Per
`(alg, model, X, F)`, both sides at the same `(model, X, F)`:

* `kappa_L(train)`, `kappa_U(train) = |M(C)| / U(train)`, `kappa_U(inf)`, `kappa_L(inf) = all_macs / L(inf)`;
* `rho_max = kappa_L(train) / kappa_U(inf)` -- *relative runtime-input efficiency*, the certified ceiling
  (provisional while `L` is unvalidated);
* `rho_ach = kappa_U(train) / kappa_U(inf)` -- what the constructive partition achieves (the adversary's known floor; trusted);
* the `(matmul MACs)` columns repeat both with `ADW_matmul_macs` (recomputes included) as the training numerator;
* `1/eta_honest = all_work / |M(C)|` of the honest training circuit (`eta` is reserved for `|M(C)| / Work(C)`);
* `U/L = kappa_L(train) / kappa_U(train)` -- the same ceiling with `B / W` matched to *honest training*
  (`B / W = 1 / kappa_U(train)`); it is `>= 1` and only measures our bound gap (`rho_ach` would be 1 there), so it is
  labelled as such.

`basis = asymptotic` uses the fitted recurring terms `r` of both circuits (`kappa = MACs/token / r`, from the P1
fits); `basis = Q=n` uses the one-`Q` values. No comparison with native HBM traffic is made (different resource).
