## What changes

- **`verity/definitions/call_scope.py`:** `specialization(fam, statics, reg=None)`. With no `reg` it reads `verity.circuits.defs.REGISTRY` as it stands, and it no longer calls `registry.catalog.load()`. The recursion passes `reg` on.
- **`verity_vllm/query/program_view.py`:** `specialization(fam, statics)` is `call_scope.specialization` over `catalog.load()[0]`, the loaded lookup for vLLM's callers. It sits beside `definition_ports`, which reads the catalog the same way. `registry/catalog.py` can't hold it, because a Definition module imports only Definition modules (`test_prims_serve_boundaries`).
- **vLLM's callers** that relied on the lazy load now call it, or pass it as `specialize`:
  - in `verity_vllm/pipeline/manifest.py`: `word_check`, `cross_call_check` and `prefetch_word_rules`;
  - `pipeline/program_graph.py`, `acquire/sources/call_boundary_plan.py`, `adapters/vllm/tools/popread.py` and `benchmarks/bool_build_cost/run.py`;
  - 14 test files under `adapters/vllm/tests/`, including the code strings that `query/test_word.py` and `pipeline/test_single_request_build_path.py` run in a subprocess.
- **`word_check`** calls `word.check_calls` over `word.call_groups` with `specialize`, which is what `word.check_query` does. `word.py` is unchanged: it stays at the 800 lines that `test_p10_size` allows.
- **The callers under `verity/` and `benchmarks/harness/`** pass `catalog.load()[0]` themselves: `verity/definitions/tests/test_word.py`, `test_call_scope.py` and `benchmarks/harness/tests/test_prove.py`.
- **`verity_flock/boolean_export.py` `_commitment`** imports every registry module (`prims()`) before it asks for a specialization.
- **`test_manifest_pool`'s stand-in `prefetch`** takes `specialize`.
- **A test,** `test_call_scope.py::test_the_family_is_the_one_the_handed_registry_holds`: an empty `DefinitionTable` names no family, so the lookup reads only the registry it is handed.
