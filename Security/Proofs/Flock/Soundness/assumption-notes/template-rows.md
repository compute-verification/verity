# A template's rows compute its gates: the evidence, the proof for RoPE, and the path for the rest

This is not a hypothesis of the end-to-end theorem (L1 was dropped, Daniel, Sep 30): the theorem is about the circuit of
the statement's rows, and what a correct unit computes is its certificate's (`IsRowsUnit.computes_of_cert`,
`../Certificate.lean`; `../ASSUMPTIONS.md`, The circuit and the certificate). The certificate's premises
are that a unit's rows are `GateRows.rows G L` for its gate circuit `G`, and that `G` computes the unit's definition. This
file is the evidence for those premises, template by template.

- **Evidence today:** the IR comparison tests in `verity/ml/flock/tests/test_ir_lowering.py`, on sampled inputs.
  - They evaluate the pinned rows against the IR's primitives:
    - RoPE on 8000 inputs (`test_rope_unit_matches_its_primitives`);
    - SiLU on every gate word and 8000 more (`test_silu_unit_covers_the_whole_table`);
    - both on the captured slices (`test_captured_slices`).
  - They evaluate the pieces the rows are built from, as gate circuits, against the IR's primitives, on 6000 inputs
    each (`test_pieces_match_the_ir_primitives`, `test_bf16_adds_match_the_ir_primitives`).
  - A test in the same file mutates one row and checks that the comparison catches it.

  They sample. They don't prove it.
- **Proved for RoPE** (`../GateRows.lean`, `../Rope/`). `Rope.rope_sound`: column values that
  satisfy the pinned `rope-head/neox-bf16/pair` rows (sha256 `9cbdef19…`), with the constant at 1, carry on output
  column `6016 + o` the gate circuit's output `o` on input columns `0 … 63`. The gate circuit is the unit's Boolean
  export (`verity_flock.boolean_export`: 64 inputs; 5,828 AND, 9,747 XOR and 1,717 NOT gates; 32 outputs). The proof
  shows that RoPE's rows compute the unit's Boolean gate circuit; that the gate circuit computes the IR's bf16 RoPE (the
  certificate's second premise) is still tested on samples (the IR comparison tests above), not proved.
  - `GateRows.rows` derives rows from any gate circuit and layout, by the v2 lowering rule: the input region, one row
    per AND in order, the output copy rows, the constant. `GateRows.rows_sound` proves that satisfied derived rows
    compute the circuit, for every circuit and layout.
  - `Rope.pinned_eq`: the pinned rows are the derived rows. The kernel checks it (`decide +kernel`, not
    `native_decide`) in 18 chunks of 1,000 gates, each from a checkpoint: the forms of the wires the rest still reads.
    A frame lemma composes the chunks (`GateRows.chunk_step`, `chunks_sound`). The checks take about 3 minutes and
    4 GB; one check over the whole unit ran out of memory at 14 GB.
  - The data (`Rope/Gates.lean`, `Pinned.lean`, `Checkpoints.lean`, `Chunks.lean`) is generated by
    `python -m verity_flock.lean_rows`. `verity/ml/flock/tests/test_lean_rope.py` regenerates it from the Boolean
    export and the pinned file and checks it byte for byte. The checkpoints need no trust: the kernel checks them.
  - Still to join: the audit reads a unit's rows as `Rows` (`../README.md` §1.5). Joining that reading to the rows
    here (`Rows.ofNet`) comes with the placement wiring (W6).
- **The path for the other templates:** the same verified lowering. Each needs its gate circuit and pinned rows as
  data, and the chunked check (`python -m verity_flock.lean_rows` generalizes from RoPE's). This matches the plan of
  record for V[B], which Lean generates with an equivalence proof.
