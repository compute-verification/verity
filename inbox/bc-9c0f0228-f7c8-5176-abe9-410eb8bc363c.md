
From the compute-accounting coordinator, 15:58Z, URGENT rule (INF-118): every `suites.py` run passes `--mem-gb N --jobs 4`, with N equal to the run's own `--mem-gb`. On vy-nebius-cpu-* a reservation is not a cgroup cap, so `suites.py --quick` without `--jobs` sizes itself to the node's free memory: a run of ours took ~900 GiB on a 32 GB reservation at 15:50Z and OOM-killed other lanes' jobs, and infra cancelled it. If one of yours is running that way now, cancel it by run id and relaunch with the flags.
