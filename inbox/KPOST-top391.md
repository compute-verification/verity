**kernels:** one piece of work, on one card. Read at main 7af4d24fca3; nothing here was run for this answer.

1. **First: the served CUDA bit for bit on `sm_103`, then its rates.** Five kernels, each through the gate it already has: the SHA-512 row hash and the row commit (the commitments' kernels), `h1u` (PoUW's H1 tile), attention's bf16 GEMMs, and the int8-exact linear. Each gate compares the card's bytes with its reference on the CPU before it times anything.
   - **GPU-hours:** about 4 on one card. One pass is about 2 hours by the gates' own lease caps (14 to 30 minutes each); a second pass repeats the rates. It fits in the first 20 node-hours.
   - **What we can't get today:** whether those bytes hold on data-center Blackwell. Ours have run on `sm_90`, `sm_120` and, in October, a B200 (`sm_100a`); none on `sm_103`. It also gives the hash rate and `h1u`'s rate there, which the commit's and PoUW's overhead on that card rest on. And one design answer: `h1u` multiplies with `mma.sync` and has no `tcgen05` path, so its rate against the card's s8 tensor rate (compute-research's line 1) says whether data-center Blackwell needs its own `h1u`.
   - **Before the node, 0 GPU-hours:** build them for `sm_103a` on our CPU node and pass the SASS gates there. No file of ours names `sm_103`. `h1u` builds for `sm_90a`, `sm_100a` and `sm_120a`, and I expect a 10.3 card to refuse an `sm_100a` cubin (not verified). Attention's gate expects an H200 by name. The SHA-512 gate builds for the card it finds, so plain `sm_103`. The int8 linear's config table has no `sm_103` row, so it runs on vLLM's default tiles: the gate still decides its bits, and its rate is untuned.
2. **Not kernels' to run:** the tensor-rate probe (one probe: compute-research's line 1), and Pearl-C and Pearl-C4 (compute-accounting's line 1). What benchmarks calls kernels' Pearl+ arm is `benchmarks/pouw/pearl_c_sm90`, compute-accounting's, built for `sm_90a` today. P2's staging is PoUS's and stays off the node unless Daniel says.
3. **Needs:** one card to itself; a driver that loads CUDA 13.0 cubins; the CUDA 13.0 toolkit and our bench venv in our own directory (about 7 GB, HTTPS out to PyPI); under 20 GB of disk. All of it is public code (Daniel, Mon 9 Nov: PoUW's kernels are fine to post).
   - **@infra:** our gates take their card with `gpu-lease`. That node needs it in user space, or a stand-in that pins one card.
   - **Root, one command for the host:** `nvidia-smi -i UUID -lgc MHZ,MHZ` before the rates, and `-rgc` after. The bit-for-bit gates need no root. Without the lock, each rate is quoted per SM-clock at the clock read.
   - No CPU node of the host's: builds and references run on ours.
