### 1. What `Spot.HistoryTable.checkAt` checks and costs

- **What it checks (read).** `checkAt` (`Spot/HistoryTable.lean:167-176` on `checked`) refuses, in order:
  - a capacity that isn't a power of two of at least 2;
  - a row of no words;
  - more rows than the capacity;
  - a `b ‖ c` string that isn't 128 bytes;
  - a registered root that isn't 64 bytes;
  - a registered root other than `rootAt cap (domainAt cap program table words) bcs (placeholder words)`.
- **What it reads (read).** Only the written rows' 128-byte `b ‖ c` strings (each row's hiding commitment), in position order. It never reads the rows, the salts or the writers' roots. Rank r's leaf binds r (`leafAt`, `:83-84`). From `bcs.size` up, every leaf is the placeholder's: the zero row under the zero salt.
- **What it costs.** It is per table, per registration that declares it: 2^17 leaves and 2^17 − 1 nodes, whatever the table's length and however many reads. Reads cost the verifier nothing here, because they are proved inside their own units. At #8357's measured 1.90 µs per 64-byte message and 3.39 µs per node, a 128k request's 78 tables take 98 core-seconds (mine).
- **Round 2 can call it as it is.** It is a pure function of `(cap, program, table, words, bcs, registered)` (read). What is one-stage is around it:
  - The domain binds the registration's program digest under the tag `verity/one-stage/history-table/v1` (`:46`, `:63-71`).
  - On #8416, the strings come from the writer members' public bodies under the registration's leaf layer, with positions mapped to one writer template's units. See `order` (`:143-162`), and #8416's `memberStrings`, `tableStrings` and `tableRoots` (`HistoryTable.lean:210`, `:233`, `:276`).
- **What changes under spans (mine).** The writers are units inside span interiors, which have public bodies only when drawn, so round 2 can't recompute the root from its writers. Two ways:
  - **(A)** Serve publishes the table's strings: 16.8 MB a table, 1.3 GB for a 128k request's 78. Hiding commitments may be public. Round 1's registration runs `checkAt` over them as held runs (`From.held`, `:97-103`).
  - **(B)** Serve registers only the root. Round 2 opens each drawn span's run of leaves against it.
  - (A) also pins the padding to the placeholder. (B) leaves the padding unchecked, which is harmless only while no read can reach it (item 3).

### 4. The candidate form

- **The tree fits spans (read).** A table's positions are "its request's latent rows at its layer in step and row order" (`history_rows.py:17`). So a span, one step's position range, owns a contiguous run of leaves, and each leaf binds its rank (`leafAt`, `:83-84`). "Its own request" is already structural: a table is one (request, layer) (`history_rows.py:15`).
- **Not as a boundary port, for three reasons (read):**
  - **Shape.** A record port's tree is `window_domain(program, partition, port, schema, leaves, run)` over exactly its own leaf count (`verity/ml/commitments/window.py:24-26`). A read opens a tree of depth 17, because `V = 2^17` is static, at whatever domain it is given. So the port would have to be the table's pinned 2^17-leaf tree, padding included, and round 1's record doesn't constrain padding.
  - **Links.** `rowsOk` (`SecondStage.lean:563-574`) gives replay block b the rows `[b·r, (b+1)·r)`, with `r = leaves / units`. So every span would have to own the same number of rows of every table, which prefill slices beside decode steps don't.
  - **Roots.** A read needs the table's root as a value. `readOk` lets a port that no link or wire names read "a value either registration registers, never a boundary port" (`:576-580`; the refusal is at `:595`).
- **What works with no change to `SecondStage.lean` (read for round 2; mine for R7).** The table's root and domain are supplied values of the boundary registration (`{"history": "<table>/root"}` on #8416), and the read units' `root` and `domain` read them. `readOk` admits "a value either registration registers" (`:596`).
  - One change is needed, and it is mine: R7 has to fill a `Digest` port. R7 lays bytes out as 32-bit halves, while a `Digest` is 64-bit words, least significant bit first (`rowleaf.digest_bits`). I'll have it, with records, by Tue 18:00Z.
- **No range check is needed in this form (mine).** A read at a position in `[start, p]` opens the same table, whose rows there are the span's own, held to it by item 5.
- **What the read needs instead:**
  - its key wired from the index (circuits' and vllm's: #8401, #8391);
  - the mask's `n` tied to the row's position in the committed step schedule (circuits' and vllm's);
  - no accepted fill row, which follows once the key is wired.
- **The alternative, which I'd set aside.** If a span's own rows came by wires and only carried rows came from the table, a read would need `LO ≤ tok < START` against two public statics. That is a new pair of statics on `EmbeddingRead_v1` or a new Definition, and it would be circuits' change. The merge would also have to split the span's own keys from carried ones. That costs more circuit for nothing the shared table doesn't already guarantee.

### 5. What a span must do so its own rows are held to the table

All mine, building on #8391's one-stage form:

- **Commit its writers' rows as table leaves.** The span's writer units (`DsaLatentRow_v1`'s `o0`) commit each row as `hm96-sha512/row-seg/v1` under the table's salt at its position. Each unit's public string is then the table's leaf. This is #8391's one-stage form today (`history_rows.py:11-13`, read).
- **A Lean check per drawn span and table.** The writer units' public strings at the span's positions, read from its sessions' public bodies as `memberStrings` reads them, must equal the table's strings there:
  - under (A), equality with the strings round 1 registered;
  - under (B), one opening of the run `[a, b)` against the registered root, about b − a + 17 hashes.

  This check belongs in `Spot.HistoryTable` and is mine. The call from round 2 is TWOPROVE's.
- **Positions to writer units from the committed step schedule, in Lean.** Today `first` and `units` come from the verifier's params.
- **A domain that binds what serve committed** (request, layer, words), so a span's strings can't be placed in another table. The tag and `program` field change. Mine, with vllm on the serve side.
- **Rows no drawn span writes are carried input.** A wrong one is caught when the span that writes it is drawn. That is the sampling guarantee, not a gap.
