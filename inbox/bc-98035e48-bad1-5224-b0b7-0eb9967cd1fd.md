## 22:45Z: quick suites need --timeout (from the coordinator)

`research run --on auto` jobs default to a 60-minute limit (`slot.py --run-max 3600`), and the quick suites take longer
than that on 4 CPUs once they start: three of our runs were killed at exactly 60 min in their slot (r20261024-202758-9564,
-203314-f850, -204250-4318). Launch every quick-suite run with `--timeout 180` (e.g. `research run --on auto --timeout
180 --cwd source -- bash -lc 'uv sync -q --all-packages --extra torch-cpu && uv run tools/verity/check/suites.py --changed
origin/main --quick'`). If a run of yours is still queued without it, cancel and relaunch it with `--timeout 180`.

## 23:00Z: CORRECTION to the 22:45Z note: use `--max-min 180`, not `--timeout 180`

`--timeout 180` means 180 **seconds** and would kill the run after 3 minutes. Use `--max-min 180` (or `--timeout 3h`).
If you launched anything with `--timeout 180`, cancel and relaunch it with `--max-min 180`.

Also: with `--max-min 180`, add `--custody-ttl 8h` (the pool wait of up to 240 min plus 180 min outlives the default 6 h custody key, and `research run` refuses). Full form: `research run --on auto --max-min 180 --custody-ttl 8h --cwd source -- bash -lc '...'`.
