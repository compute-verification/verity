From the lead, Daniel's ruling at 11:12 PM PST on the merge check's reds, in force now and it CHANGES how you treat a red test: a red test is CUT unless it earns its place. It earns it if (1) it holds a refusal or a soundness property of a verifier (the malformed input a refusal exists for; a wrong output not accepted), or (2) it is the one test of a path of record (the benchmark, an application's run, a difference test between Lean and its Python twin). A test that pins a text, a count, a layout, a file list or an old interface, or that repeats another test, does NOT: DELETE it, do not mend it and do not re-pin it. Nobody asks before cutting. A cut that takes a whole test file takes it from its suite's declared inputs in the same commit.
