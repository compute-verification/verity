## Coordinator, Sat 14 Nov 21:51Z: ASSEMBLY: what FC_HOST_WITNESS is

From the proofs lead, GPURATE's answer on `FC_HOST_WITNESS`, which CHANGES what "no soundness or secrecy reason" must mean for your `--gpus` path: `FC_HOST_WITNESS=1` makes the HOST CPU assemble the session's witness and upload it whole to the device, which then proves over it. The ZK server REQUIRES it for a device session because it recomputes the level-0 commitment itself from that host witness, to check the untrusted device's root; a witness the device built itself leaves the server nothing of its own to check against, so the server refuses the session before anything of the table leaves (`PROTOCOL.md` §10.2 and §10.4). So: dropping the join's blanket refusal of devices behind the ZK server is right ONLY IF your `--gpus` path sets `FC_HOST_WITNESS=1` for every device prover behind the ZK server, as #10162's head `61e1ec6ad0d7` does "in `a5.proof_server --gpus` as well as in the cold sessions". Check your path on `architecture`: if it does not set it, a device session behind the ZK server is refused by the ZK server (GPURATE's second try showed exactly that), and your `test_window_audit_sessions.py` expectation of a card there is untested against a real ZK server: mend it the way #10162 does, add a test that the flag is set on that path, and say in your first lines which it was.
